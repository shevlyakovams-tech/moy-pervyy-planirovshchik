# Отчёт итоговой технической приёмки

Текущая редакция `tz.md` содержит ровно 83 нумерованных критерия приёмки. Команда `npm run acceptance:verify` извлекает их непосредственно из ТЗ и проверяет наличие автоматического доказательства для каждой функциональной группы. Скрипт не подменяет запуск тестов: он контролирует полноту матрицы, а фактический результат подтверждается полным прогоном команд ниже.

| Группа | Критериев | Основное доказательство |
|---|---:|---|
| Доступность и адаптивность | 4 | Axe WCAG A/AA, клавиатура, focus trap, reduced motion, 360/768/1024/1200/1920 |
| Даты, день, настроение, задачи и неделя | 23 | модульные, интеграционные и Playwright-проверки шагов 2 и 9 |
| Привычки, планка, отжимания и вода | 20 | модульные, интеграционные и Playwright-проверки шагов 3–6 |
| Цитаты, прогресс и поиск | 13 | проверки колоды, истории, фильтров, графиков и внешних запросов |
| Знакомство | 3 | модульная и сквозная проверка первоначального запуска |
| Уведомления и полный сброс | 8 | внедряемые часы, расписания, транзакционный reset и интерфейс подтверждения |
| Запуск, миграции, безопасность, журнал и лицензии | 12 | supervisor/Electron, синтетическая миграция, security/logger и license audit |
| **Всего** | **83** | **все группы связаны с существующими проверками** |

Обязательный технический прогон:

```text
npm run typecheck
npm run lint
npm test
npm run test:database
npm run test:performance
npm run licenses:check
npm run acceptance:verify
npm run build
npm run test:e2e
```

Отдельно проверяются `setup.bat`, `start.bat` и Electron lifecycle. Финальная оценка внешнего вида, удобства, звука, уведомлений на реальном Windows и работа при физически отключённой сети остаются ручной продуктовой приёмкой владельца, как требует `plan.md`.
